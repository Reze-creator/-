# 代码阅读指南

先运行页面闭环，再按入口、服务、规则、SQL、测试的顺序阅读。

## 预约

BookingController → BookingService → BookingServiceImpl。create展示事务模板、资源锁、占用查询、指纹；pay/cancel遵守资源锁在前、预约锁在后。BookingRules是时间校验，BookingMapper是重叠SQL。新增IN_USE、COMPLETED表示实际使用与完成，前端按钮不代替服务端检查。

## 履约

DeviceController接收管理员模拟事件，UsageServiceImpl.receive处理幂等和收件箱，drain只取下一连续序号，SessionRules先验证，apply再修改，所以业务校验失败不会留下半更新会话。

EXIT调用SettlementService接口，SettlementServiceImpl必须加入原事务，BillingRules计算分钟和金额，账单两个唯一键防重。电量为累计量，单纯上报电表不结算。小时单价取预约快照，电价入场复制到会话。

## 运营与界面

DeviceServiceImpl处理心跳，OperationsServiceImpl.report按来源去重，scan发现离线缺号超时，resolve先检查恢复条件。OperationsJob只调业务接口。TraceFilter记录请求标识与计时，不写请求体或凭证。

SimulatorView保存固定事件号批次，网络重试不换号；UsageView以all属性复用本人与平台列表；OperationsView显示异常、审计、当前进程指标。

## 约定与注释

Controller只路由、校验和组织响应，不访问Mapper/Entity。ServiceImpl间用接口，SQL放Mapper，纯规则放common。构造器注入，DTO/VO/Entity分离，Java格式由Google Java Format、前端由Prettier统一。

中文注释重点说明为什么先锁资源、为什么回滚后重读、为什么不能越过缺号、为什么不能累加累计电量、为什么结算需要已有事务，不给每行赋值堆重复注释。

## 验证

PhaseTwoContractSuite验证计费、乱序、幂等冲突、失败队列、跳过、恢复、权限、并发结算和故障回滚，分别运行于H2与真实MySQL。PaymentBoundaryTest用可控Clock及真实MyBatis INSERT阻塞复现支付截止竞争，确认第二次预约等待资源锁并在支付提交后被拒绝。

隔离压测通过parking_test和8091实例执行，原始数据在docs/performance/latest.json。读项目时关注保证的业务条件、实现机制及可复现测试，再根据实际瓶颈扩展技术。
