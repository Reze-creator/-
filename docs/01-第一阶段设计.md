# 第一阶段：最小可用版本

## 范围

车主注册登录、查资源、按时段预约、模拟支付、取消与模拟退款、我的预约；管理员查看全量预约和启停资源。Vue3前端随Spring Boot打包，8090一个地址即可使用。实际使用本机MySQL，新建parking业务库与parking_test测试库；不依赖Redis、RabbitMQ或虚拟机。

第一阶段暂用USER与ADMIN两个角色；后续增加园区运营角色。充电车位包含功率信息，但本阶段费用仅为预约时段的停车费用，不包含电费，不进行设备控制或真实支付。

## 业务规则

- 所有API时间使用带时区的ISO8601；数据库UTC，界面按Asia/Shanghai展示。
- 预约开始时间必须晚于服务器当前时间、最多提前30天；起止必须对齐上海时区的整点或半点；时长30分钟至24小时。
- 预约区间为[start,end)，前一单结束时间等于后一单开始时间允许预约。
- 待支付保留5分钟，且最晚到预约开始；到期不再占用资源，定时任务每30秒将状态更新为EXPIRED。查询和支付也识别到期状态，不依赖定时任务及时运行。
- 支付为模拟渠道，一次性支付预约时段的停车费，单价保存快照。费用按半小时精确计算，使用BigDecimal，不含电费。
- 允许在开始时间前取消。未支付直接取消，已支付同事务标记模拟退款成功；重复取消或支付幂等，不重复记账。开始后不允许主动取消。
- 已取消或到期的预约不阻塞资源；CONFIRMED只在它的预约区间阻塞，不用一个永久OCCUPIED字段锁死资源。
- 资源停用阻止新预约，不自动取消已有预约。已有订单仍可支付、查询、取消；管理员启停时界面明确提示。

## 并发与事务

创建预约时，事务使用READ_COMMITTED，首先锁资源行SELECT FOR UPDATE，再检查重叠记录并创建预约。所有创建入口都使用同一资源锁，防止并发先查后插。不同资源互不串行，同一资源的创建请求串行；这是简单第一版的明确取舍。

同用户+requestId唯一；对资源、车牌、起止时间做输入摘要。重复相同请求返回原预约，不延长保留期；改输入返回409。摘要使用规范化的Instant，不区分等价时区写法。并发唯一键竞争者在自己的事务结束后读取胜者记录。

支付和取消都锁预约行，完成状态转换及支付表写入；订单到期任务按状态条件更新，与支付锁形成串行判定。到期支付返回当前EXPIRED对象，不生成支付单。MySQL事务保证业务事实一致，不引入分布式锁或跨系统事务。

## 三层结构

controller负责HTTP；service接口/impl负责业务、事务与DTO转换；mapper负责SQL；entity为数据库对象；dto为输入；vo为输出。使用MyBatis-Plus简化CRUD，显式SQL执行行锁和条件更新。Flyway管理schema。

登录使用BCrypt校验密码，随机Bearer token只向客户端返回原文，数据库保存SHA-256摘要和有效期。USER仅访问本人预约；ADMIN可全量查看但不能替车主支付或取消。前端使用sessionStorage保存当前标签页会话，登出删除服务端会话。演示账号只用于本机开发。
