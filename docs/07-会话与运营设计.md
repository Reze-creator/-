# 会话与运营设计

本文为第二阶段基线；当前异步事件处理、缓存与搜索设计以[中间件设计与接口](11-中间件设计与接口.md)补充更新。

版本2.0.0，2026-11-07。AI与RAG按最新要求暂缓。本轮实现设备模拟、停车充电会话、实际费用模拟结算、运营异常、监控与压测。

## 业务模型

预约负责计划，usage_session负责实际履约，usage_bill负责最终费用。原booking.amount是预约时段预付款，最终账单分别列停车费、电费、预付、补付、退回。mock_payment的SETTLED表示已计入最终账单，REFUNDED仍只用于未履约预约取消时的全额退款。

预约新增IN_USE与COMPLETED。入场转IN_USE，离场结算转COMPLETED；已入场不能取消。已完成单释放原预约剩余时段。同资源最多一个未离场会话，前车未离场时后车入场失败，处理后可重试。预约可用性仍是计划时段判断，前车超时通过工单处理。

## 持久化事件收件箱

事件字段有eventId、bookingId、sequenceNo、类型、发生时间和累计电量。eventId主键与预约+序号唯一键防重复，指纹为内容的SHA-256；同ID同内容重放返回原事件，改内容或同序号换ID返回409。

接收先锁资源再锁预约，保存WAITING，仅处理 `last_event_sequence+1`，每次最多100条。第3条先到不会越过缺失的第2条。队列存数据库，重启仍保留缺号事件，无MQ依赖。

业务校验错误存FAILED并生成EVENT_FAILURE工单，后序等待。数据库或结算异常回滚接收事务，客户端重发原eventId。HTTP200只表示接收成功，必须读取data.status。

| 事件 | 前置条件 | 结果 |
| --- | --- | --- |
| ENTER | 已支付，尚无会话，位于预约区间，资源无活动会话 | PARKED，预约IN_USE |
| CHARGE_STARTED | 充电车位，PARKED，未充过电，电量0 | CHARGING |
| METER_REPORTED | CHARGING，时间和累计电量不回退 | 更新累计kWh |
| CHARGE_STOPPED | CHARGING，电量不回退 | PARKED，保存最终电量 |
| EXIT | 已入场且未充电，时间晚于入场，电量不变 | FINISHED，生成唯一账单，预约COMPLETED |

时间精度最多毫秒，最长会话48小时，一次一段充电。序号1..10000，新序号不超过游标+100。模拟事件允许未来预约时间，真实时间控制登录、保留期、心跳、扫描；管理员入口不能直接当真实设备公网协议。

## 锁与事务

创建锁资源，支付、取消、事件处理统一资源锁在前、预约锁在后。创建、支付、取消和事件处理使用READ_COMMITTED，获锁后读最新状态。资源启停与心跳也锁资源。

这修正第一阶段文档中的截止竞争：支付检查通过后，即使提交跨截止，新建仍等待同一资源锁；获锁后能看到CONFIRMED，不能当过期待支付插入重叠单。PaymentBoundaryTest以可控时钟及真实MyBatis INSERT阻塞验证。

离场会话、账单、预付、预约、事件状态与游标在同事务提交。SettlementService使用MANDATORY要求已有事务。账单booking_id和session_id各自唯一。故障注入测试验证结算抛错全回滚，原EXIT重放后仅一账单。

## 计费

停车分钟向上取整实际毫秒差÷60000；停车费=小时单价快照×分钟÷60；电费=最终累计kWh×入场电价快照；金额HALF_UP到两位。总额减预付款，正值模拟补付，负值模拟退回。

例如6元/小时预约3小时预付18元，实际1小时用电10kWh，电价1.20，总额18元，补退0。普通停车实际30分钟费用3元，预付6元则模拟退3元。客户端不能提交金额；SIMULATED_SETTLED不代表真实渠道成功。

## 增量数据库

V2迁移新增6表，保留V1历史，共11张业务表（不含Flyway历史）。booking增加last_event_sequence默认0。

| 表 | 重要字段约束 |
| --- | --- |
| simulated_device | id同资源，心跳、故障及说明 |
| usage_session | booking_id唯一，用户资源、入离场充电时间、累计电量、电价快照 |
| device_event | eventId主键、booking_id+sequence_no唯一，指纹、内容、处理状态错误 |
| usage_bill | booking_id和session_id各自唯一，费用和补退明细 |
| operation_incident | source_type+source_id唯一，异常、状态、处理人与说明 |
| operation_audit | 操作者、动作、对象、原因、请求标识、时间 |

字段类型、索引、外键以V2 SQL、Entity与DTO为准。不修改已执行V1，不清业务库。

## 运营闭环

默认120秒心跳超时OFFLINE，故障心跳FAULT，未有心跳UNKNOWN。心跳不自动改变预约资源enabled，运营可自行停用。每30秒扫描离线、WAITING超过30秒、活动会话超过预约结束，按来源去重，复发重新开单。

RETRY把失败或等待事件重新排队；SKIP只允许跳过当前阻塞的下一条已存在事件，必须写原因、记审计。跳过不制造会话、电量或结算，仍需正确后续事件。关单先验证设备正常未离线、事件已应用或跳过、超时会话已结束。

资源启停、心跳、事件、重试、跳过、手动扫描、关单都记录管理审计。服务器日志包含请求标识、方法、路由模板、状态和耗时，不记录凭证或请求体。Micrometer使用路由模板而非实际订单ID，避免高基数。指标为当前进程，重启清零，无外部告警或长期存储。
