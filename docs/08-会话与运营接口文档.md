# 会话与运营接口文档

版本2.0.0，基地址 http://localhost:8090，JSON，时间ISO8601带时区，金额元、电量kWh。原预约新增IN_USE、COMPLETED状态和SETTLED支付投影。AI暂缓。

统一外层 `{code,message,data,requestId}`，认证头 `Authorization: Bearer <token>`。除本人会话、账单外，本页接口均仅ADMIN。分页 `page=1&size=20`，size最大100，返回 `{items,page,size,total}`，按created_at和id降序。

## 心跳

正文 `{"fault":false,"message":""}`。fault必填布尔，message可选最多200字符。true生成故障工单，false恢复设备但不自动关单。响应DeviceView：id、resourceCode、parkName、type、status、lastSeenAt、faultMessage；status=UNKNOWN/ONLINE/OFFLINE/FAULT。

## 设备事件

```json
{
  "eventId":"apifox-enter-001",
  "bookingId":"替换为已支付预约ID",
  "sequenceNo":1,
  "type":"ENTER",
  "occurredAt":"2026-11-08T09:00:00+08:00",
  "energyKwh":0
}
```

示例ID和日期需替换。eventId为1..64位字母数字下划线连字符；bookingId必填；sequenceNo=1..10000且不超过游标+100；时间精度最多毫秒；energyKwh必填0..10000且最多3位小数。类型ENTER、CHARGE_STARTED、METER_REPORTED、CHARGE_STOPPED、EXIT。

同ID同输入重发返回当前事件；同ID改输入或同序号换ID返回409。电量为会话累计，5→10表示累计10，不是15。业务错误HTTP200但status=FAILED，不能只看HTTP成功。

EventView：id、bookingId、sequenceNo、type、occurredAt、energyKwh、status、errorMessage、createdAt。状态WAITING等待前序、APPLIED已应用、FAILED失败阻塞后序、SKIPPED人工跳过。

充电演示：序号1入场电量0、2开充0、3电表5、4停充10、5离场10；可按5、4、3、2、1倒序提交，最终仍只有一会话一账单。入场在预约区间内，离场最多距入场48小时。

## 事件处理

正文 `{"action":"RETRY","reason":"前车已离场，重新处理"}`。action=RETRY/SKIP，reason必填非空白最多500字。RETRY重排WAITING/FAILED，SKIP只跳过游标下一条已存在事件，不能凭空跨号。已应用或跳过事件重复调用返回原结果。跳过不自动伪造会话、电量或退款。

## 会话与最终账单

UsageView：id、bookingId、resourceCode、parkName、type、plateNumber、status、enteredAt、chargingStartedAt、chargingStoppedAt、exitedAt、energyKwh、energyRate、lastSequence。会话状态PARKED/CHARGING/FINISHED，未发生时间为null。

BillView：id、bookingId、sessionId、resourceCode、parkingMinutes、parkingAmount、energyKwh、energyRate、energyAmount、totalAmount、prepaidAmount、additionalAmount、refundAmount、status、createdAt。status固定SIMULATED_SETTLED。

费用例：停车60分钟6元，用电10kWh电价1.20，电费12元，总18元，预付6元，模拟补12元退0元。普通用户只有自己的列表；管理员用admin前缀看全平台。

## 工单审计与指标

关单正文 `{"resolution":"恢复正常心跳并确认设备正常"}`，非空白最多500字，未恢复业务条件返回409。IncidentView：id、sourceType、sourceId、resourceId、bookingId、title、detail、status、resolution、createdAt、resolvedAt。

来源DEVICE_FAULT、DEVICE_OFFLINE、EVENT_FAILURE、EVENT_GAP、SESSION_OVERRUN。重复扫描去重，复发可重开，重复关已解决工单返回当前结果。

AuditView：id、actorId、action、targetId、detail、requestId、createdAt。requestId与日志对应。overview包含openIncidents、activeSessions、waitingEvents、failedEvents、settledBills、sampledAt、heapUsedBytes、http；http项有route、status、count、totalMs、maxMs，平均为totalMs/count。指标重启清零，max为时间窗口最大值。

## Apifox

导入docs/apifox-openapi.json，配置token、resourceId、bookingId、startAt、endAt。运行scripts/export-openapi.ps1刷新契约。网络失败重发原eventId，不要直接换号；新业务事件才生成新ID。
